# 作業記録 009: Gitブランチ・PR・レビュー工程の追加
作成日: 2026-07-30

## 概要
- 課題: Codexの基本的なファイル変更作業へGitブランチ・PR・レビュー工程を追加する
- 目的: baseブランチへ直接変更せず、課題単位の差分をPRで検証・レビューできる運用にする
- 完了条件: ブランチ作成からPR作成後のレビュー・CI確認までがルール化され、今回の変更でも同工程を実行している

## 適用した役割
### Portfolio Planner
- 入力: ファイル変更時にCodexがブランチ作成、PR作成、レビューまで行う要件
- 実施内容: dirty worktree保護、命名、commit、push、PR、CI、レビュー対応、認証例外を含む標準工程を設計
- 成果物: Git/PRワークフローの追加方針
- 検証結果: 既存のCodex役割委任・Issue・検証ルールと接続できることを確認
- 未解決事項: なし
- 次工程への引き継ぎ: Frontend Engineer相当の主担当Codexへ文書実装を引き継ぎ

### Portfolio Frontend Engineer
- 入力: Plannerの設計と既存の`AGENTS.md`
- 実施内容: 課題用ブランチを作成し、`AGENTS.md`、`README.md`、IssueテンプレートへGit/PR工程を追加
- 成果物: 作業開始前確認、ブランチ命名、commit、PR事前レビュー、push、PR作成後レビュー、CI、認証例外のルール
- 検証結果: 文書構造、Git差分、Issue命名、必須キーワードを確認
- 未解決事項: GitHub CLIの保存済み認証が無効。push時に利用可能なGit認証を確認する
- 次工程への引き継ぎ: Reviewerへbaseとの差分レビューを依頼

### Portfolio Reviewer
- 入力: baseとの差分、要件、検証結果、作業記録
- 実施内容: PR作成前レビューでCIのない場合の完了条件と自己承認の表現を確認し、中程度2件を指摘
- 成果物: CIの有無を考慮した完了条件と、自己承認を外部承認として扱わない明確なルール
- 検証結果: 指摘2件を修正。再レビューは重大0件・中0件で合格
- 未解決事項: なし
- 次工程への引き継ぎ: 再レビュー合格後にscoped staging、commit、push、PR作成

## 主要な判断
- 判断: ファイル変更では原則としてCodexが課題用ブランチからReady PR作成とレビュー対応まで行う
- 理由: baseへの直接変更を避け、変更内容と検証結果を追跡可能にするため
- 判断: PRのマージとブランチ削除は自動化しない
- 理由: 公開・統合に相当する最終判断は、ユーザーの明示指示を必要とするため
- 判断: Codex自身のGitHub上の自己承認を正式承認として扱わない
- 理由: サブエージェントレビューとCI結果は記録できるが、独立した外部承認を偽装しないため
- 判断: PR作成以外の通常Git工程は、初回の限定的な永続許可後に自動実行する
- 理由: 安全な定型操作の承認回数を減らしつつ、PR作成・マージ・ブランチ削除・破壊的操作はユーザー判断として残すため
